最近重构了 Obsidian 笔记的自动同步脚本，从最初的粗糙版本升级到现在的生产级状态。这半个月的迭代，让我对自动化脚本的健壮性设计有了更深的理解。

如果你也在维护类似的同步工具，或许这些经验能给你一些参考。

---

### 从"能用就行"到"真正可靠"

最早版本的脚本只有 30 行，配置写死，日志随意增长。网络一卡，推送失败，脚本就报错退出，还得手动处理。

这次重构的核心目标就一个：**让工具真正隐形**——你运行它，然后忘记它，它自己搞定一切。

---

### 核心改进点

**1. 环境变量配置支持**

告别硬编码路径：

```bash
REPO_PATH="${REPO_PATH:-/default/path}"
LOG_FILE="${LOG_FILE:-/tmp/git-auto-sync.log}"
```

这意味着同一个脚本可以在多台设备上运行，只需通过环境变量覆盖配置。

**2. 日志自动轮转**

日志不控制的话会无限膨胀。我实现了一个标准的日志轮转机制：

- 超过 10MB 自动压缩归档
- 保留最近 5 个压缩文件
- 自动清理 7 天前的旧日志
- 兼容 macOS 和 Linux 的 `stat` 命令差异

关键是这个架构：先检查大小 → 压缩当前 → 重命名旧文件 → 清理超限。

**3. Git 配置持久化**

原版每次 `git push` 都要传 `-c http.lowSpeedLimit=xxx`，既繁琐又不优雅。现在的做法是：第一次运行时在仓库级配置，后续直接复用。

```bash
git config http.lowSpeedLimit 1000
git config http.lowSpeedTime 999
```

一次设置，永久生效。

**4. 指数退避重试（最重要的改进）**

网络不稳定是常态，push 失败不应该直接报错退出：

```bash
retry_count=0
delay=5
while [ $retry_count -lt 3 ]; do
    if git push; then success; break; fi
    sleep $delay
    delay=$((delay * 2))
done
```

5秒 → 10秒 → 20秒，最多试3次。大多数网络抖动都能自动恢复。

---

### 可配置参数一览

| 变量名 | 作用 |
|-------|------|
| `MAX_LOG_SIZE` | 日志轮转阈值（默认 10MB）|
| `MAX_LOG_FILES` | 保留的压缩文件数（默认 5）|
| `MAX_RETRIES` | 推送最大重试次数（默认 3）|
| `RETRY_DELAY` | 初始重试延迟（默认 5 秒）|

---

### 使用方式

```bash
# 基本用法
./git-sync.sh

# 自定义配置
export MAX_LOG_SIZE=5242880  # 5MB 轮转
export MAX_RETRIES=5          # 重试5次
./git-sync.sh

# crontab 定时同步（自带锁防止并发）
*/5 * * * * /path/to/git-sync.sh >> /dev/null 2>&1
```

完整脚本约 200 行，已保存至仓库根目录（`git-sync.sh`）。

### 写在最后

自动化工具的价值，不是让你更忙，而是让你**忘记它的存在**。

一个真正好用的脚本，应该像水电一样：你打开开关，它就开始工作；你不需要理解它是怎么发电的，也不需要担心它会突然断掉。

这次重构的目标就是靠近这个理想。脚本依然可以继续优化，比如引入邮件通知、支持多分支、添加更详细的统计等。但现阶段，它已足够稳定，可以放心扔进 crontab，让它默默工作。
